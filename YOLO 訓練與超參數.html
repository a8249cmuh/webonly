YOLO 訓練與超參數

從訓練、調參數，到用模型做預測，再做成網頁介面。第一、三、四部分的程式可以直接複製貼上；第二部分逐項說明參數，並用互動圖表示範早停、資料擴增、輸出位置與接續訓練；第三部分用互動圖看 conf 與 iou 如何篩選偵測框。範例使用 yolo26n.pt。

官方文件（中文）：docs.ultralytics.com/zh。預設值以近期 Ultralytics 版本為準，不同版本可能略有差異。若找不到 yolo26n.pt，先執行 pip install -U ultralytics。

超參數介紹

2-1　data.yaml 資料集設定檔

model.train(data=...) 指向的就是這個檔案。它告訴 YOLO 兩件事：資料集放在哪裡，以及有哪些類別。

YAML 是什麼？

YAML 是一種給人看、也給程式讀的設定檔格式，副檔名是 .yaml 或 .yml。它用冒號、縮排與清單表示資料，比 JSON 少了大括號與引號，容易手寫；缺點是縮排和空格錯一點，就讀不進來。YOLO 的 data.yaml、訓練後產生的 args.yaml、模型結構檔（例如 yolo26n.yaml）都是 YAML。

語法範例說明
鍵值對epochs: 300冒號後面一定要有一個空格
縮排表示階層names: 的下一行縮排 2 格，寫 0: plate只能用空格縮排（不能用 Tab），同一層的縮排要一致
清單- helmet，或 ['a', 'b']每個項目一行，以 - 開頭；也可以寫在一行的方括號內
註解# 這是註解從 # 到行尾都會被忽略
字串path: D:/Python/yolo通常不用加引號；內容含 : 或 # 等特殊字元時才加引號
數字與布林nc: 2、true、false數字不要加引號，否則會被當成文字

data.yaml 的欄位

欄位意思範例
path資料集根目錄。建議用絕對路徑，並用正斜線 /D:/Python/yolo/train001
train訓練圖片的位置，相對於 path。可以是資料夾，也可以是列出圖片路徑的 .txt 檔images/train
val驗證圖片的位置，寫法同 trainimages/val
test測試圖片的位置，可省略images/test
nc類別數量。新版可省略，會依 names 自動計算；寫了就要和 names 的數量一致1
names類別名稱。編號從 0 開始，順序要和標註檔裡的編號一致0: plate

資料夾結構與標註檔

YOLO 的規則：把圖片路徑裡的 images 換成 labels，再把副檔名換成 .txt，就是那張圖的標註檔。所以兩個資料夾的結構要一模一樣。

每個標註檔一個物件一行，格式是 class_id x_center y_center width height，五個數字以空格分隔：

欄位意思
class_id類別編號，對應 names 的編號，從 0 開始
x_center框的中心點 x，除以圖片寬度，範圍 0~1
y_center框的中心點 y，除以圖片高度，範圍 0~1
width框的寬度，除以圖片寬度，範圍 0~1
height框的高度，除以圖片高度，範圍 0~1

圖片裡沒有任何目標時，標註檔可以是空的，也可以不放。如果路徑裡沒有 images 這個資料夾，標註檔就必須和圖片放在同一個資料夾。

    2-2　基本訓練參數

    參數意思預設值 / 建議
    data指向 data.yaml（內含訓練集、驗證集路徑與類別名稱）。內容與寫法見 2-1。Windows 路徑在字串前加 r，\ 就不會被當成跳脫字元。必填
    epochs訓練輪數。完整看過一次全部訓練資料算 1 輪。太大且資料少時容易過擬合，建議先跑 100~300 輪再看曲線調整。預設 100
    建議 100~300
    imgsz輸入影像邊長（像素），圖片會縮放到此大小。小物件偵測可提高，但更吃記憶體。640
    batch每次餵進模型的圖片張數，每處理完一個 batch 更新一次權重。受 GPU 記憶體限制，不是越大越好；記憶體不足會出現 CUDA out of memory。設 -1 可依顯卡記憶體自動估算。16
    常用 16、32、64
    patience連續幾輪驗證成績沒進步就提早停止。看的是驗證集的 fitness（約為 0.1×mAP50 + 0.9×mAP50-95 的加權）。設 0 表示關閉早停。100

    為什麼需要早停？拖曳 patience 看看

    這是模擬曲線。訓練集表現會一路上升，驗證集表現到某一輪之後反而下降，這就是過擬合。早停的規則：驗證成績連續 patience 輪沒有創新高，就停止訓練，並保留最佳的那一輪（best.pt）。

    2-3　資料擴增參數

    資料擴增是把訓練圖片做隨機變化（旋轉、位移、變色等），讓模型看到更多樣的情況，降低過擬合。新版 Ultralytics 在訓練時預設就會做擴增，由下列參數控制強度；想關閉某種擴增，把對應參數設為 0 即可。

    參數意思預設值本講義
    degrees隨機旋轉，範圍 ±degrees 度0.015
    translate平移：圖片隨機上下左右位移最多 ±比例，超出邊界的部分被切掉，所以看起來像裁切0.10.2
    scale縮放，範圍為 1 ± scale。0.5 表示 0.5~1.5 倍0.50.5
    shear剪切：圖片像平行四邊形般歪斜，範圍 ±shear 度0.020
    flipud上下翻轉的機率（0~1）0.00
    fliplr左右翻轉的機率（0~1）0.50
    hsv_h色相偏移幅度。太大會讓顏色失真（紅變綠）0.0150.015
    hsv_s飽和度變化幅度0.70.2
    hsv_v明度變化幅度，可模擬光線明暗0.40.2
    mosaic每張訓練圖有此機率被替換成 4 張圖拼貼，對小物件與背景變化有幫助1.0預設
    close_mosaic最後 N 輪自動關閉 mosaic，讓模型在較接近真實的圖片上收尾10預設

    資料擴增實驗室

    左上角是原圖，其餘是依目前參數隨機抽出的 5 個樣本。金色虛線框是 YOLO 標註框：旋轉或剪切之後，框會變大。把 fliplr 拉到 1，看看車牌上的字會變成什麼樣子。

    為什麼 flipud、fliplr 設為 0？

    文字、數字、車牌這類任務有方向性，翻轉後會變成鏡像字，反而干擾學習。一般物體偵測（人、車、安全帽）左右翻轉是合理的，建議保留預設 fliplr=0.5。

    為什麼 hsv_h 不宜太大？

    色相偏移太多，顏色會變得不真實。如果顏色是辨識關鍵（例如不同顏色的安全帽），請維持小值。

    2-4　硬體與加速

    參數意思預設值 / 建議
    device指定運算裝置。編號從 0 開始，單張顯卡就是 device=0；多張顯卡可用 list，例如 [0, 1]；'cpu' 使用 CPU。GPU 記憶體不足時，通常先調小 batch 或 imgsz，比改用 CPU 實際（CPU 訓練時間會很久）。自動選擇
    amp混合精度（FP16）訓練，可用 Tensor Cores 加速。預設就是開啟，訓練開始時會自動做相容性檢查，不相容的 GPU 會自動關閉。True
    通常不用改
    workers資料載入的執行緒數。Windows 上若訓練卡住或報錯，可改為 0 或較小的值。8
    cache把圖片快取到記憶體（True 或 'ram'）或硬碟（'disk'），加速訓練。資料量不大時很實用。False

    2-5　中斷、接續與輸出位置

    參數意思預設值
    resume接續中斷的訓練。必須先載入 last.pt，再執行 model.train(resume=True)；第一次訓練不要設定。若載入的是預訓練權重（如 yolo26n.pt），沒有訓練進度可接續，會報錯。False
    project輸出的上層資料夾，可有組織地存放不同實驗。在 Colab 設成 Google 雲端硬碟路徑，斷線後 last.pt 不會消失。runs/detect
    name子資料夾名稱，實際輸出路徑為 project/name。不指定時，每次訓練會自動產生 train、train2、train3…train
    exist_ok設為 True 時，同名資料夾直接使用，不再自動加編號。False
    save_period每 N 輪另外存一份檢查點（epochN.pt）。last.pt 與 best.pt 不受影響，一直都會存。-1（不另存）

    我的 last.pt 會在哪裡？

    輸入你的設定，看看結果會寫到哪個資料夾。

    resume 是什麼意思？

    訓練時，每跑完一輪，Ultralytics 都會把「檢查點」存成 last.pt。裡面不只有模型權重，還有已經訓練到第幾輪、優化器的狀態，以及原本的訓練設定（資料集、epochs、batch…）。resume=True 的意思是：依 last.pt 裡記錄的進度與設定，從中斷的那一輪繼續訓練。所以它必須搭配 last.pt，其餘參數不用再填。

    拖曳看看：中斷在第幾輪？

    載入的權重與指令結果
    YOLO('last.pt') + train(resume=True)從中斷的那一輪接續，沿用原本設定
    YOLO('yolo26n.pt') + train(resume=True)預訓練權重沒有訓練進度，無法接續，會報錯
    YOLO('yolo26n.pt') + train(...)從頭開始一次新的訓練
    YOLO('last.pt') + train(新參數)以舊成果當起點，開一次新的訓練（輪數重新計算）

    Colab 斷線後的接續步驟

    1. 重新連線，重新掛載雲端硬碟。
    2. 重新安裝並匯入 ultralytics（/content 清空後，套件也消失了）。
    3. 確認資料集還在原本訓練時的路徑。接續時會沿用原本記錄的路徑，不在就要重新解壓或複製回來。
    4. 載入雲端硬碟裡的 last.pt，不是 yolo26n.pt。
    5. 執行 model.train(resume=True)。程式碼見第一部分的 1-3。

    訓練已經跑完（達到原本設定的 epochs）就不需要也無法接續。想再多訓練，請用 last.pt 當起點開新訓練，並設定新的 epochs。

    2-7　使用建議速查

    epochs 先設 100~300，並保留 patience=100，不要同時設很大的 epochs 又關閉早停。
    有方向性的任務（文字、數字、車牌）關閉 flipud 與 fliplr。
    顏色是辨識關鍵時，hsv_h 維持小值。
    在 Colab 訓練一定要把 project 設到雲端硬碟，並記得用 last.pt 接續。
    GPU 記憶體不足時，先調小 batch 或 imgsz。
    不同版本的預設值可能不同，遇到警告或錯誤時，對照 官方文件 確認。
    第三部分

    Predict 預測

    訓練完成後，用 best.pt 對新圖片、影片或攝影機畫面做偵測，這個步驟叫 predict（推論）。

    3-6　predict 常用參數

    參數意思預設值
    source要預測的來源：圖片路徑、資料夾、影片、網址，或 0（第一支攝影機）必填
    conf信心門檻，低於這個分數的偵測框會被丟掉。調高：誤判少，但可能漏掉；調低：漏掉少，但誤判多0.25
    iouNMS 的重疊門檻。兩個框的重疊程度（IoU）超過這個值，只留分數較高的那個0.7
    imgsz推論時的影像大小，建議和訓練時相同640
    device運算裝置，用法同訓練自動選擇
    save是否把畫好框的圖片或影片存起來（Python 預設不存）False
    save_txt輸出 YOLO 格式的標註檔（.txt）False
    save_conf搭配 save_txt，標註檔裡多存信心分數False
    save_crop把每個偵測框裁切成小圖存起來（例如車牌，之後可交給 OCR）False
    show開視窗即時顯示（Colab 不能用）False
    classes只保留指定類別，例如 [0] 或 [0, 2]None（全部）
    max_det每張圖最多保留幾個偵測框300
    streamTrue 時逐幀回傳結果，處理影片或攝影機時節省記憶體False
    vid_stride影片每隔幾幀處理一次，數字越大越快1
    project / name / exist_ok輸出位置，規則和訓練相同runs/detect/predict

    3-7　conf 與 iou：偵測框怎麼被篩選

    模型對一張圖會先產生很多「候選框」，每個都有信心分數。predict 依序做兩件事：

    1. conf 篩選：分數低於 conf 的框直接丟掉。太低，會把招牌、車燈誤判成車牌；太高，較小、較模糊的車牌分數本來就低，會被漏掉。
    2. NMS（非極大值抑制）：同一個目標常有好幾個重疊的框。依分數排序，留下最高分的，其餘和它重疊程度（IoU）超過 iou 的框都刪掉。iou 太高，重複的框刪不掉；太低，緊鄰的兩個不同目標可能被誤刪成一個。

    拖曳 conf 與 iou，看偵測框怎麼變

    場景裡有 3 個真正的車牌，加上招牌與車燈 2 個容易被誤判的地方。每個框旁邊是模型給的信心分數。

    第四部分

    Gradio 圖形介面

    Gradio 是一個 Python 套件，用幾行程式就能把函式包成網頁介面：使用者在瀏覽器上傳圖片、拉滑桿、按按鈕，Gradio 把輸入交給你的函式，再把回傳值顯示在網頁上。不需要寫 HTML、CSS 或 JavaScript，很適合把訓練好的 YOLO 模型做成讓同學或客戶試用的小工具。官方網站：gradio.app

    4-1　Gradio 是什麼

    Gradio 怎麼運作

    你只需要寫中間那一層：一個接收輸入、回傳結果的 Python 函式，其餘交給 Gradio。

    寫法特色適合
    gr.Interface一個函式、固定版面，程式最少快速示範
    gr.Blocks自訂版面、多個按鈕與事件想控制畫面配置、顯示表格等

    4-2　常用元件

    元件用途
    gr.Image圖片輸入或輸出。type='pil' 給函式 PIL 影像；sources=['upload', 'webcam'] 可選上傳或攝影機
    gr.Video影片輸入或輸出
    gr.Slider滑桿，例如 conf、iou
    gr.Textbox文字輸入或輸出
    gr.Dropdown / gr.CheckboxGroup下拉選單、多選框，例如只顯示指定類別
    gr.Dataframe表格，例如偵測明細
    gr.Label顯示分類結果與機率
    gr.Button按鈕，用 .click() 綁定要執行的函式
    gr.Markdown顯示文字（支援 Markdown 語法）
    gr.Row / gr.Column / gr.Tab版面容器：橫排、直排、分頁
