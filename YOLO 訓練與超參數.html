YOLO 訓練與超參數

從認識 YOLO26、上傳資料集、訓練、調參數，到用模型做預測，再做成網頁介面。第零部分介紹 YOLO26；第一、三、四部分的程式可以直接複製貼上，第一部分也說明怎麼把資料集壓縮後上傳 Colab；第二部分逐項說明參數，並用互動圖表示範早停、資料擴增、輸出位置與接續訓練；第三部分用互動圖看 conf 與 iou 如何篩選偵測框，並示範在 Colab 播放 YouTube 串流的推論畫面。範例使用 yolo26n.pt。

官方文件（中文）：docs.ultralytics.com/zh。預設值以近期 Ultralytics 版本為準，不同版本可能略有差異。若找不到 yolo26n.pt，先執行 pip install -U ultralytics。

第零部分

YOLO26 是什麼

YOLO26 是 Ultralytics 在 2026 年 1 月正式發布的模型家族，主打「端到端、免 NMS」與邊緣裝置部署。官方表示 YOLO26n 相較 YOLO11n，CPU（ONNX）推論最多快約 43%。本講義的 yolo26n.pt 就是其中最小的 n 版本。

官方文件對照：YOLO26 模型介紹 ↗、端到端（免 NMS）偵測 ↗

0-1　四個重點改良

原生端到端、免 NMS

內建 One-to-One 偵測頭，推論時加上 nms=False 就直接輸出結果，不需要再做 NMS 後處理。

移除 DFL

拿掉 Distribution Focal Loss，偵測頭更輕，匯出 ONNX、TensorRT 等格式更單純。

新的訓練配方

MuSGD（SGD 與 Muon 的混合優化器）、ProgLoss（漸進式損失）、STAL（小目標感知的標籤分配）。

七種任務

偵測、實例分割、語意分割、深度估計、分類、姿態、旋轉框（OBB）；另有開放詞彙版 YOLOE-26。

0-2　雙偵測頭：預設還是會做 NMS

YOLO26 同時訓練兩個偵測頭。predict() 預設走 One-to-Many 頭，仍然會做 NMS（第三部分 3-7 的互動圖就是這個流程）；要用免 NMS 的端到端推論，必須自己加上 nms=False。

0-3　五種尺寸（COCO 偵測，640 像素）

n、s、m、l、x 由小到大。上課與 Colab 免費 GPU 建議用 n 或 s；檔名把 yolo26n.pt 的 n 換掉即可。

1-5　Colab 資料集上傳：壓縮與解壓縮

官方文件對照：偵測資料集格式 ↗

幾千張圖片直接拖進 Colab，每個檔案都是一次獨立的上傳，會非常慢。先在自己電腦把整個資料集資料夾壓成一個 zip，上傳一次，再在 Colab 裡解壓縮，會快很多。訓練完的結果資料夾也一樣，先壓縮再下載。

步驟 1：在自己電腦壓縮

壓縮時選「整個 dataset 資料夾」（裡面有 images、labels、data.yaml）。解壓到 /content 之後，路徑剛好是 /content/dataset，和 1-2 Colab 版與 2-1 Colab 範本的 data.yaml 一致。

系統滑鼠操作指令
Windows資料夾按右鍵 → 壓縮成 ZIP 檔案（Win10：傳送到 → 壓縮的資料夾）Compress-Archive -Path dataset -DestinationPath dataset.zip（PowerShell；超過 2 GB 建議改用 7-Zip）
macOS資料夾按右鍵 → 壓縮zip -r dataset.zip dataset -x "*.DS_Store" "__MACOSX/*"
RoboflowExport → 選 YOLO 格式 → Download zip已經是 zip，直接上傳。注意它的資料夾是 train/images、valid/images，data.yaml 要照下面的分頁修改

步驟 2、3：上傳、解壓縮，訓練完再壓縮下載

常用指令速查

指令用途
!unzip -q a.zip -d /content解壓縮 zip，-q 不列出每個檔名（幾千個檔案時一定要加，否則輸出會塞爆畫面）
!unzip -o -q a.zip -d /content已有同名檔案時直接覆蓋，不會停下來詢問
!unzip -l a.zip | head -20只看壓縮檔內容（前 20 行），不解壓，可先確認資料夾結構

!tar -xzf a.tar.gz -C /content解壓縮 .tar.gz
!tar -czf b.tar.gz 資料夾壓成 .tar.gz
!du -sh /content/dataset查看資料夾大小
!rm /content/dataset.zip解壓後刪掉 zip，節省空間

解壓後多一層資料夾

zip 裡如果已經有一層 dataset/，又解壓到 /content/dataset，就會變成 /content/dataset/dataset/。所以解壓到 /content，並先用 !ls 看清楚實際路徑再填 data.yaml。

Colab 斷線就會清空

/content 裡解壓出來的資料，工作階段結束就會消失。zip 放在雲端硬碟，下次重新掛載後再解壓一次即可（1-3 接續訓練的步驟 3）。

不要直接在雲端硬碟上訓練

訓練時會反覆讀取幾千張圖，從雲端硬碟讀很慢。一定要解壓到 /content 本機磁碟再訓練；只有 project 輸出設到雲端硬碟。

檔名用英文

資料夾與圖片檔名建議用英文、數字、底線，可以避免中文亂碼與路徑錯誤。

2-1　data.yaml 資料集設定檔

官方文件對照：偵測資料集格式 ↗、COCO 資料集 ↗

model.train(data=...) 指向的就是這個檔案。它告訴 YOLO 兩件事：資料集放在哪裡，以及有哪些類別。

YAML 是什麼？

YAML 是一種給人看、也給程式讀的設定檔格式，副檔名是 .yaml 或 .yml。它用冒號、縮排與清單表示資料，比 JSON 少了大括號與引號，容易手寫；缺點是縮排和空格錯一點，就讀不進來。YOLO 的 data.yaml、訓練後產生的 args.yaml、模型結構檔（例如 yolo26n.yaml）都是 YAML。

語法範例說明
鍵值對epochs: 300冒號後面一定要有一個空格
縮排表示階層names: 的下一行縮排 2 格，寫 0: plate只能用空格縮排（不能用 Tab），同一層的縮排要一致
清單- helmet，或 ['a', 'b']每個項目一行，以 - 開頭；也可以寫在一行的方括號內
註解# 這是註解從 # 到行尾都會被忽略
字串path: D:/Python/yolo通常不用加引號；內容含 : 或 # 等特殊字元時才加引號
數字與布林nc: 2、true、false數字不要加引號，否則會被當成文字

data.yaml 的欄位

欄位意思範例
path資料集根目錄。建議用絕對路徑，並用正斜線 /D:/Python/yolo/train001
train訓練圖片的位置，相對於 path。可以是資料夾，也可以是列出圖片路徑的 .txt 檔images/train
val驗證圖片的位置，寫法同 trainimages/val
test測試圖片的位置，可省略images/test
nc類別數量。新版可省略，會依 names 自動計算；寫了就要和 names 的數量一致1
names類別名稱。編號從 0 開始，順序要和標註檔裡的編號一致0: plate

資料夾結構與標註檔

YOLO 的規則：把圖片路徑裡的 images 換成 labels，再把副檔名換成 .txt，就是那張圖的標註檔。所以兩個資料夾的結構要一模一樣。

每個標註檔一個物件一行，格式是 class_id x_center y_center width height，五個數字以空格分隔：

欄位意思
class_id類別編號，對應 names 的編號，從 0 開始
x_center框的中心點 x，除以圖片寬度，範圍 0~1
y_center框的中心點 y，除以圖片高度，範圍 0~1
width框的寬度，除以圖片寬度，範圍 0~1
height框的高度，除以圖片高度，範圍 0~1

圖片裡沒有任何目標時，標註檔可以是空的，也可以不放。如果路徑裡沒有 images 這個資料夾，標註檔就必須和圖片放在同一個資料夾。

    2-3　資料擴增參數

    官方文件對照：資料增強指南 ↗、配置參數總表 ↗

    資料擴增是把訓練圖片做隨機變化（旋轉、位移、變色等），讓模型看到更多樣的情況，降低過擬合。新版 Ultralytics 在訓練時預設就會做擴增，由下列參數控制強度；想關閉某種擴增，把對應參數設為 0 即可。

    參數意思預設值本講義
    degrees隨機旋轉，範圍 ±degrees 度0.015
    translate平移：圖片隨機上下左右位移最多 ±比例，超出邊界的部分被切掉，所以看起來像裁切0.10.2
    scale縮放，範圍為 1 ± scale。0.5 表示 0.5~1.5 倍0.50.5
    shear剪切：圖片像平行四邊形般歪斜，範圍 ±shear 度0.020
    flipud上下翻轉的機率（0~1）0.00
    fliplr左右翻轉的機率（0~1）0.50
    hsv_h色相偏移幅度。太大會讓顏色失真（紅變綠）0.0150.015
    hsv_s飽和度變化幅度0.70.2
    hsv_v明度變化幅度，可模擬光線明暗0.40.2
    mosaic每張訓練圖有此機率被替換成 4 張圖拼貼，對小物件與背景變化有幫助1.0預設
    close_mosaic最後 N 輪自動關閉 mosaic，讓模型在較接近真實的圖片上收尾10預設

    資料擴增實驗室

    左上角是原圖，其餘是依目前參數隨機抽出的 5 個樣本。金色虛線框是 YOLO 標註框：旋轉或剪切之後，框會變大。把 fliplr 拉到 1，看看車牌上的字會變成什麼樣子。

    為什麼 flipud、fliplr 設為 0？

    文字、數字、車牌這類任務有方向性，翻轉後會變成鏡像字，反而干擾學習。一般物體偵測（人、車、安全帽）左右翻轉是合理的，建議保留預設 fliplr=0.5。

    為什麼 hsv_h 不宜太大？

    色相偏移太多，顏色會變得不真實。如果顏色是辨識關鍵（例如不同顏色的安全帽），請維持小值。

    輸入你的設定，看看結果會寫到哪個資料夾。

    resume 是什麼意思？

    訓練時，每跑完一輪，Ultralytics 都會把「檢查點」存成 last.pt。裡面不只有模型權重，還有已經訓練到第幾輪、優化器的狀態，以及原本的訓練設定（資料集、epochs、batch…）。resume=True 的意思是：依 last.pt 裡記錄的進度與設定，從中斷的那一輪繼續訓練。所以它必須搭配 last.pt，其餘參數不用再填。

    拖曳看看：中斷在第幾輪？

    載入的權重與指令結果
    YOLO('last.pt') + train(resume=True)從中斷的那一輪接續，沿用原本設定
    YOLO('yolo26n.pt') + train(resume=True)預訓練權重沒有訓練進度，無法接續，會報錯
    YOLO('yolo26n.pt') + train(...)從頭開始一次新的訓練
    YOLO('last.pt') + train(新參數)以舊成果當起點，開一次新的訓練（輪數重新計算）

    Colab 斷線後的接續步驟

    1. 重新連線，重新掛載雲端硬碟。
    2. 重新安裝並匯入 ultralytics（/content 清空後，套件也消失了）。
    3. 確認資料集還在原本訓練時的路徑。接續時會沿用原本記錄的路徑，不在就要從雲端硬碟的 zip 重新解壓（指令見 1-5）。
    4. 載入雲端硬碟裡的 last.pt，不是 yolo26n.pt。
    5. 執行 model.train(resume=True)。程式碼見第一部分的 1-3。

    訓練已經跑完（達到原本設定的 epochs）就不需要也無法接續。想再多訓練，請用 last.pt 當起點開新訓練，並設定新的 epochs。

    3-7　conf 與 iou：偵測框怎麼被篩選

    官方文件對照：預測模式（Predict） ↗

    模型對一張圖會先產生很多「候選框」，每個都有信心分數。predict 依序做兩件事：

    1. conf 篩選：分數低於 conf 的框直接丟掉。太低，會把招牌、車燈誤判成車牌；太高，較小、較模糊的車牌分數本來就低，會被漏掉。
    2. NMS（非極大值抑制）：同一個目標常有好幾個重疊的框。依分數排序，留下最高分的，其餘和它重疊程度（IoU）超過 iou 的框都刪掉。iou 太高，重複的框刪不掉；太低，緊鄰的兩個不同目標可能被誤刪成一個。

    拖曳 conf 與 iou，看偵測框怎麼變

    場景裡有 3 個真正的車牌，加上招牌與車燈 2 個容易被誤判的地方。每個框旁邊是模型給的信心分數。

    保留的框 NMS 刪掉的重複框 conf 丟掉的框

    3-10　在 Colab 推論 YouTube 串流並顯示畫面

    官方文件對照：預測模式：推論來源 ↗

    Colab 沒有 OpenCV 視窗，show=True 與 cv2.imshow() 都不能用；cv2_imshow（3-5）放在迴圈裡會每一幀新增一張圖，輸出越來越長。做法是先建立一個可更新的輸出位置，每推論完一幀，就把畫好框的影像轉成 JPG，換掉上一張，畫面就會像影片一樣播放。

    Waiting for stream 0 是什麼

    這不是錯誤。Ultralytics 用另一條執行緒讀串流，推論比畫面送來得快時就會印出這行，意思是「下一幀還沒到」。verbose=False 擋不掉，要用 logging 把等級調到 ERROR。

    設定位置不能放錯

    setLevel 要寫在 from ultralytics import YOLO 之後。Ultralytics 在 import 時會重設訊息等級，放在前面會被蓋掉。想看回警告，把 logging.ERROR 改成 logging.INFO。

    流暢度

    每一幀都要從 Colab 傳回瀏覽器，通常每秒只有幾幀，適合示範；vid_stride 調大可以跳過更多幀，畫面跟得比較上。

    YouTube 擋下載

    Colab 是雲端機房的 IP，YouTube 有時會要求「Sign in to confirm you're not a bot」。這時在自己電腦用 yt-dlp 下載影片，壓縮上傳後用第二個分頁的做法推論。
