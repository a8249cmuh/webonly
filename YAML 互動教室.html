YAML 從哪裡來？

YAML 和 JSON 一樣是「用文字記錄資料」的格式，但它更在乎人讀起來舒不舒服：不用大括號、少用引號，靠縮排表示層級，還能寫註解。所以它特別常被拿來寫「設定檔」。

名字的故事

今天在哪裡會遇到 YAML？

  • 🎯
    AI 模型訓練設定YOLO 的 data.yaml 記錄資料集路徑與類別名稱；許多訓練超參數也寫成 YAML。
  • ⚙️
    GitHub Actions.github/workflows/*.yml 描述自動測試、自動部署的流程。
  • 🐳
    Docker Compose／Kubernetes用 YAML 描述要啟動哪些服務、開哪些連接埠。
  • 📝
    部落格與文件Hugo、Jekyll 文章開頭的 front matter（標題、日期、標籤）。
  • 🔌
    API 規格OpenAPI（Swagger）規格檔常用 YAML 撰寫。

    PART 1 · 第 2 章
    
語法規則：縮排就是結構

    
JSON 用括號表示層級，YAML 用空白縮排。看起來清爽，但多一個、少一個空白，意思就完全不同。

  

  

    
1
用縮排表示層級
同一層要對齊；只能用空白鍵，不能用 Tab。建議每層 2 個空白。
student:
  name: 王小明

    
2
冒號後面一定要空白
鍵和值用「冒號 + 空白」分隔。少了空白，整串會被當成文字。
age: 19 ✅   age:19 ❌

    
3
清單用「- 」開頭
每個項目前面放「減號 + 空白」，同一個清單的 - 要對齊。
- 籃球
- Scratch

    
4
# 開頭是註解
這是 JSON 做不到的！# 到行尾都會被忽略，很適合寫說明。
# 學生基本資料

    
5
字串通常不用加引號
但內容有「: 」「 #」、或像 yes、3.10 這種會被誤判的值，就要加引號。
version: "3.10"

    
6
大小寫有差、--- 分隔文件
Name 和 name 是不同的鍵。一個檔案可以用 --- 放多份文件。副檔名 .yaml 或 .yml。

YAML vs JSON
YAML 1.2 是 JSON 的「超集合」：合法的 JSON 幾乎都能直接當 YAML 讀。

    

    

      
比較項目YAMLJSON

      
層級表示縮排（空白）{ } 和 [ ]

      
字串引號大多可省略一定要雙引號

      
註解可以用 #不行

      
重複利用錨點 & 與別名 *沒有

      
多行文字| 和 > 很方便只能寫 \n

      
適合用途人要常常手改的設定檔程式之間交換資料、API

      
缺點縮排錯一格就出事；型態可能被誤判括號、逗號多，不能寫註解

資料型態：YAML 會「猜」型態

    
YAML 的值大多不加引號，解析器會依照寫法自動判斷它是字串、數字、布林還是空值。這很方便，但也是 YAML 最容易踩雷的地方。

對應 Mapping：鍵: 值

序列 Sequence：一排有順序的值

    
序列（sequence）相當於 JSON 的陣列、Python 的 list。每一項用「- 」開頭；索引一樣從 0 開始。也可以寫成一行的流式風格 [88, 92, 75]。

0
索引從 0 開始
第 1 項是 [0]，最後一項是 [長度 - 1]，也可以用 [-1] 從後面數。

    
-
對應放進序列
- name: 王小明 的下一行 age 要和 name 對齊（比 - 多兩格），它們才屬於同一項。

    
[ ]
區塊 vs 流式
短的清單用 [a, b, c] 一行寫完；長的或巢狀的用「- 」比較好讀。兩種寫法意思完全相同。
